# US-03: เก็บผลตอบแทนลงคลัง พร้อมชุดข้อมูลจำลอง

**Epic แม่:** [`./epic.md`](./epic.md) · **Status:** 🟢 Ready (S1) · เส้นทาง: ⚪ → 🟡 → **🟢 Ready** → 🔨 In Dev → ✅ Done
**Priority:** P0 · **Session:** S2 · **Roadmap:** [Phase 0 · feature 0.3](../../../ROADMAP.md) · **Route:** ไม่มี (ชั้นคลังข้อมูล) · **Data mode:** live + จำลอง

> **ในฐานะ** ผู้ใช้ที่ลองปรับพอร์ตซ้ำหลายรอบ **ฉันต้องการ** ให้การขอข้อมูลชุดเดิมเร็วทันทีและไม่พึ่งว่าแหล่งข้อมูลภายนอกจะว่างหรือไม่ **เพื่อที่จะ** ทดลองไอเดียได้ต่อเนื่องโดยไม่ต้องรอทุกครั้ง

**หลักที่ยึด:** P3 เร็วพอที่จะลองซ้ำหลายรอบ · P1 เลขเชื่อถือได้

---

## บริบท & เงื่อนไขก่อนหน้า (Context & Preconditions)

- [US-02](./US-02-monthly-normalization.md) แปลงข้อมูลเป็นผลตอบแทนรายเดือนได้แล้ว
- ผลตอบแทนของ**เดือนที่ปิดแล้วไม่มีวันเปลี่ยน** ต่างจากราคาปรับแล้วซึ่งเปลี่ยนได้ทุกครั้งที่มีปันผลรอบใหม่
- ที่เก็บต่างกันตามสภาพแวดล้อม: เครื่องพัฒนาเก็บเป็นไฟล์บนดิสก์ได้ ส่วนเครื่องที่ให้บริการจริงเขียนไฟล์ถาวรไม่ได้

## กฎทางธุรกิจ (Business Rules)

| Rule ID | กฎ | เจ้าของค่า | Priority |
| --- | --- | --- | --- |
| BR-CCH-01 | **คลังเก็บผลตอบแทนรายเดือน ไม่เก็บราคา** เพราะผลตอบแทนของเดือนที่ปิดแล้วคงที่ถาวร ส่วนราคาปรับแล้วเปลี่ยนย้อนหลังได้ | ชั้นคลังข้อมูล | P0 |
| BR-CCH-02 | ผลตอบแทนของเดือนที่ปิดแล้วเก็บถาวร ไม่มีวันหมดอายุ | ชั้นคลังข้อมูล | P0 |
| BR-CCH-03 | ผลตอบแทนของเดือนที่เพิ่งปิด ให้ถือว่ายังไม่นิ่งตลอด **7 วันปฏิทินแรกของเดือนใหม่** (แหล่งข้อมูลอาจแก้ไขย้อนหลังในช่วงต้น) — ระหว่างนั้นเก็บได้แต่หมดอายุใน 24 ชั่วโมง พ้น 7 วันแล้วถือเป็นถาวรตาม BR-CCH-02 | ชั้นคลังข้อมูล | P1 |
| BR-CCH-04 | ที่เก็บอยู่หลังสัญญาเดียว ผู้เรียกไม่รู้ว่าเบื้องหลังเป็นไฟล์บนเครื่องหรือที่เก็บภายนอก การสลับที่เก็บต้องไม่กระทบผู้เรียกเลย | ชั้นคลังข้อมูล | P0 |
| BR-CCH-05 | คีย์ของข้อมูลคือ สัญลักษณ์ + เดือน หนึ่งเดือนของหนึ่งสัญลักษณ์มีค่าเดียว | ชั้นคลังข้อมูล | P0 |
| BR-CCH-06 | เมื่อคำขอครอบคลุมช่วงที่คลังมีบางส่วน ให้ขอจากแหล่งข้อมูลเฉพาะส่วนที่ขาด แล้วนำมาต่อกัน โดยส่วนที่ดึงใหม่ต้องเป็นช่วงต่อเนื่องที่คำนวณอัตราส่วนภายในตัวเองได้ตาม BR-NRM-04 | ชั้นคลังข้อมูล | P0 |
| BR-CCH-07 | คลังข้อมูลล้มเหลวต้องไม่ทำให้คำขอล้มเหลว ถ้าอ่านหรือเขียนคลังไม่ได้ ให้ทำงานต่อโดยขอจากแหล่งข้อมูลตรง | ชั้นคลังข้อมูล | P1 |
| BR-CCH-08 | ชุดข้อมูลจำลองให้ผลเหมือนเดิมทุกครั้ง ไม่พึ่งเครือข่าย ไม่พึ่งเวลาปัจจุบัน และใช้สัญญาเดียวกับแหล่งข้อมูลจริงทุกประการ | ชั้นข้อมูล | P0 |
| BR-CCH-09 | ชุดข้อมูลจำลองประกอบด้วย fixture เหล่านี้เป็นอย่างน้อย (ชื่อคือสัญลักษณ์ที่ใช้เรียกจริงในโหมดจำลอง):<br>• **VTI, VNQ, VXUS, BND, SPY** — ชุดอ้างอิงครบ ม.ค. 2012 ถึง มิ.ย. 2026 (ตรง golden fixture)<br>• **RF** — ชุดอัตราปราศจากความเสี่ยงรายเดือนตาม BR-FND-03<br>• **NEWFUND** — มีข้อมูลตั้งแต่ ม.ค. 2020 (สั้นกว่าช่วงเต็ม — ใช้ทดสอบการย่อช่วง/N-001)<br>• **DOWNONLY** — ทำจุดสูงสุดแล้วลงต่อเนื่องจนจบโดยไม่ฟื้น (ใช้ทดสอบกรณียังไม่ฟื้นของ US-10)<br>• **UPONLY** — ไม่มีเดือนติดลบเลย (ใช้ทดสอบ Sortino ไม่มีค่า)<br>• **ERRNET** — ตอบเป็น "ติดต่อแหล่งข้อมูลไม่ได้" เสมอ (ใช้เดินเส้นทาง E-001 บน route)<br>• **ZZZZZ** — ตอบว่าไม่พบสัญลักษณ์ | ชั้นข้อมูล | P0 |
| BR-CCH-10 | ข้อมูลในคลังไม่ถูกนำขึ้นระบบควบคุมเวอร์ชัน เพราะดึงใหม่ได้เสมอและทำให้ประวัติบวม | ชั้นคลังข้อมูล | P1 |

## แผนตรวจสอบ (Verification Plan)

- **ชุดทดสอบ:** ที่เก็บแบบในหน่วยความจำสำหรับทดสอบ + แหล่งข้อมูลปลอมที่นับจำนวนครั้งที่ถูกเรียก ครอบทุก AC โดยเฉพาะ: เรียกซ้ำแล้วไม่ยิงออก (AC-CCH-01), เติมเฉพาะช่วงที่ขาด (AC-CCH-02), เดือนสดหมดอายุ (AC-CCH-04), คลังพังแล้วยังทำงานได้ (AC-CCH-05)
- **ชุดข้อมูลจำลอง:** ทดสอบว่าเรียกสองครั้งได้ค่าเท่ากันทุกตัว และครอบคลุมสัญลักษณ์ตาม BR-CCH-09
- **ตรวจด้วยตา 1 ครั้ง:** ยืนยันว่าข้อมูลคลังไม่ถูกนำขึ้นระบบควบคุมเวอร์ชันตาม BR-CCH-10
- **Guards:** lint · tsc · vitest
