# US-02: แปลงราคารายวันเป็นผลตอบแทนรายเดือน

**Epic แม่:** [`./epic.md`](./epic.md) · **Status:** 🟢 Ready (S1) · เส้นทาง: ⚪ → 🟡 → **🟢 Ready** → 🔨 In Dev → ✅ Done
**Priority:** P0 · **Session:** S2 · **Roadmap:** [Phase 0 · feature 0.2](../../../ROADMAP.md) · **Route:** ไม่มี (ชั้นข้อมูล) · **Data mode:** live + จำลอง

> **ในฐานะ** เครื่องคำนวณที่ต้องได้ตัวเลขตรงมาตรฐาน **ฉันต้องการ** ผลตอบแทนรายเดือนที่รวมปันผลแล้วและนิยามชัดเจน **เพื่อที่จะ** ให้ค่าที่คำนวณออกมาเทียบกับเครื่องมือมาตรฐานได้จริง

**หลักที่ยึด:** P1 เลขเชื่อถือได้

---

## บริบท & เงื่อนไขก่อนหน้า (Context & Preconditions)

- [US-01](./US-01-price-provider-us.md) ดึงข้อมูลดิบจากแหล่งได้แล้ว
- แหล่งข้อมูลให้ราคาปิดรายวัน**แบบปรับแล้ว** ซึ่งสะท้อนทั้งการจ่ายปันผลและการแตกพาร์
- ราคาปรับแล้วของอดีต**เปลี่ยนได้**ทุกครั้งที่มีการจ่ายปันผลรอบใหม่ (ตัวปรับใหม่คูณย้อนลงไปทั้งชุด) แต่**อัตราส่วนระหว่างสองเดือนไม่เปลี่ยน** เพราะตัวปรับคูณทั้งตัวตั้งและตัวหารเท่ากัน

## กฎทางธุรกิจ (Business Rules)

| Rule ID | กฎ | เจ้าของค่า | Priority |
| --- | --- | --- | --- |
| BR-NRM-01 | ตัวแทนของแต่ละเดือนคือราคาปิดแบบปรับแล้วของ**วันทำการสุดท้ายที่มีข้อมูลในเดือนนั้น** ไม่ใช่วันสุดท้ายตามปฏิทิน | ชั้นข้อมูล | P0 |
| BR-NRM-02 | ผลตอบแทนของเดือน M = (ราคาตัวแทนเดือน M ÷ ราคาตัวแทนเดือน M−1) − 1 | ชั้นข้อมูล | P0 |
| BR-NRM-03 | เดือนแรกสุดของชุดข้อมูลไม่มีผลตอบแทน (ไม่มีเดือนก่อนหน้าให้เทียบ) จึงไม่ปรากฏในผลลัพธ์ ผลลัพธ์เริ่มที่เดือนที่สอง | ชั้นข้อมูล | P0 |
| BR-NRM-04 | ราคาสองจุดที่ใช้หารกันตาม BR-NRM-02 **ต้องมาจากการดึงข้อมูลรอบเดียวกัน** ห้ามนำราคาที่เก็บไว้เดิมมาหารกับราคาที่เพิ่งดึงใหม่ เพราะสองชุดอาจอยู่คนละสเกลการปรับปันผล ทำให้ผลตอบแทนของเดือนรอยต่อผิด | ชั้นข้อมูล | P0 |
| BR-NRM-05 | เดือนที่ยังไม่ปิดตาม BR-FND-01 ไม่ถูกแปลงเป็นผลตอบแทน และไม่ปรากฏในผลลัพธ์ | ชั้นข้อมูล | P0 |
| BR-NRM-06 | ถ้าเดือนใดไม่มีข้อมูลราคาเลย ห้ามเติมค่าแทน ห้ามข้ามไปหารกับเดือนที่ไกลกว่า ให้ตัดชุดข้อมูลที่จุดนั้นแล้วระบุว่าข้อมูลต่อเนื่องถึงเดือนไหน | ชั้นข้อมูล | P0 |
| BR-NRM-07 | ผลตอบแทนเก็บเป็นสัดส่วนทศนิยม (0.021 หมายถึง 2.1%) การแปลงเป็นเปอร์เซ็นต์และการปัดเศษเป็นหน้าที่ของหน้าจอ ไม่ใช่ของชั้นข้อมูล | ชั้นข้อมูล | P0 |
| BR-NRM-08 | เดือนถูกระบุด้วยปีและเดือนเท่านั้น (เช่น 2012-01) ไม่มีวันที่ เพื่อไม่ให้เขตเวลาหรือวันหยุดของแต่ละตลาดทำให้เดือนคลาดกัน | ชั้นข้อมูล | P0 |
| BR-NRM-09 | ผลตอบแทนที่คำนวณได้ต้องเป็นตัวเลขที่ใช้งานได้เสมอ ถ้าราคาตัวแทนของเดือนก่อนหน้าเป็นศูนย์หรือติดลบ ให้ถือว่าข้อมูลเสียตาม BR-NRM-06 | ชั้นข้อมูล | P0 |
