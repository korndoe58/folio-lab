# Epic: เทียบพอร์ตและจำลองเงินเข้าออก (compare-cashflows)

**Status:** 🟢 Ready (S14) · เส้นทาง: ⚪ → 🟡 → **🟢 Ready** → 🔨 In Dev → ✅ Done
**Roadmap:** [Phase 2 — features 2.1–2.6](../../../ROADMAP.md) · **Session:** S14 author · S15, S15b, S16 implement
**ลำดับ:** ทำหลังเฟส 3 ตาม [PD-011](../../decision-log.md)

> **อ่านก่อน (TL;DR)**
> - คำถามจริงของนักลงทุนแทบไม่เคยเป็น "พอร์ตนี้ได้เท่าไร" แต่เป็น "**พอร์ตนี้ดีกว่าอีกอันไหม**"
> - epic นี้ทำให้ตั้งได้ถึง 3 พอร์ตแล้วดูทุกกราฟทุกตารางซ้อนกัน โดยเปลี่ยนทีละตัวแปร
> - และจำลองพฤติกรรมจริงได้: **ใส่เงินเพิ่มทุกเดือน (DCA) หรือถอนออก** กับ **วิธีปรับสมดุลพอร์ต**
> - เมื่อมีเงินเข้าออก ตัวเลข "ผลตอบแทนต่อปี" มีสองความหมายที่ต่างกันจริง — จอต้องแยกให้ชัด
>   ไม่งั้นผู้ใช้อ่านผิดแล้วตัดสินใจลงทุนผิด
> - ปิดท้ายด้วยมุมมองที่ฆ่าอคติเรื่องจังหวะเข้า (ผลตอบแทนแบบหน้าต่างเลื่อน) และการเอาผลออกไปใช้ต่อ

## §1 ปัญหา (Problem)

วันนี้เครื่องมือตอบได้แค่ "พอร์ตนี้ให้ผลเท่าไร" ทีละพอร์ต แต่คำถามที่คนถามจริงเป็นเชิงเปรียบเทียบเสมอ —
"เพิ่มทองคำ 10% ดีขึ้นไหม" · "ปรับสมดุลทุกปีคุ้มกับความยุ่งยากหรือเปล่า" · "ทยอยซื้อทุกเดือนกับลงทีเดียว
อันไหนดีกว่า" ทุกคำถามพวกนี้ต้องเห็นสองผลลัพธ์**พร้อมกันบนหน้าจอเดียว** ถ้าให้เปิดสองแท็บแล้วจำตัวเลข
มาเทียบเอง คนจะเทียบผิดหรือเลิกเทียบไปเลย

ปัญหาที่สองหนักกว่า: เครื่องมือสมมติว่าใส่เงินก้อนเดียวตอนต้นแล้วไม่แตะอีกเลย ซึ่งไม่ใช่พฤติกรรมของ
คนส่วนใหญ่ที่ทยอยลงทุนทุกเดือน หรือของคนเกษียณที่ทยอยถอนออก **ผลของพอร์ตเดียวกันต่างกันมาก**
ระหว่างสองพฤติกรรมนี้ และไม่มีวิธีรู้เลยด้วยเครื่องมือปัจจุบัน

## §2 ผู้ใช้ (Persona)

นักลงทุนรายย่อยที่จัดพอร์ตเองและกำลังชั่งใจระหว่างทางเลือกที่ต่างกันนิดเดียว — อ่านผลตอบแทนและ
ความเสี่ยงพื้นฐานเป็น แต่ไม่ได้เรียนการเงินมา จึงไม่รู้ว่า "ผลตอบแทนต่อปี" มีได้มากกว่าหนึ่งนิยาม
และจะเชื่อตัวเลขที่เห็นบนจอตรง ๆ · ส่วนใหญ่ทยอยลงทุนรายเดือนมากกว่าลงทีเดียว

## §3 คุณค่า & ตัววัดความสำเร็จ (Value & Success Metric)

- **คุณค่า:** ตอบคำถามเชิงเปรียบเทียบได้ในหน้าจอเดียว และจำลองวิธีลงทุนที่ผู้ใช้ทำจริงได้
- **ตัววัด (วัดได้):**
  1. เทียบ 3 พอร์ตพร้อมกันแล้วทุกกราฟและทุกตารางแสดงครบทั้งสามชุด โดยแยกออกจากกันได้โดยไม่พึ่งสี
  2. ผลของการทยอยลงทุนและการปรับสมดุลตรวจทานกับการคำนวณมือได้อย่างน้อยอย่างละหนึ่งกรณี
  3. **ลิงก์ที่แชร์เปิดซ้ำแล้วได้ผลเหมือนเดิมทุกหลัก** รวมทั้งลิงก์ที่แชร์ไปก่อนมี epic นี้
  4. พอร์ตที่ไม่มีเงินเข้าออกและตั้งค่าปรับสมดุลแบบเดิม ให้ผลเท่าเดิมทุกหลักกับก่อนมี epic นี้
  5. ผู้ใช้ที่เห็นตัวเลขผลตอบแทนบนพอร์ตที่มีเงินเข้าออก อ่านออกได้เองว่าค่าไหนวัดอะไร
- **หลักที่ยึด:** P1 เลขเชื่อถือได้ (หลัก) · P2 เข้าใจได้โดยไม่ต้องจบการเงิน · P4 แชร์/ทำซ้ำผลได้

## §4 ขอบเขต (Scope)

**อยู่ในขอบเขต:**
- ตั้งค่าและเทียบพอร์ตได้ถึง 3 ชุดในการรันเดียว พร้อมชื่อพอร์ตที่ผู้ใช้ตั้งเอง
- ทุกส่วนของผลลัพธ์ (ตารางสรุป · กราฟมูลค่า · ผลตอบแทนรายปี · ช่วงขาดทุน) แสดงทุกพอร์ตพร้อมกัน
- เงินเข้าออกระหว่างทางแบบคงที่รายเดือน/รายไตรมาส/รายปี ทั้งใส่เพิ่มและถอนออก และเลือกให้
  จำนวนเงินเพิ่มตามเงินเฟ้อได้
- วิธีปรับสมดุล: ไม่ปรับ · รายเดือน · รายไตรมาส · รายปี · ปรับเมื่อน้ำหนักเบี่ยงเกินที่กำหนด
- ผลตอบแทนแบบหน้าต่างเลื่อน 1/3/5/10 ปี
- ตารางผลตอบแทนรายเดือน + ส่งออกเป็นไฟล์ตารางคำนวณ
- ปุ่มคัดลอกลิงก์ผลลัพธ์

**นอกขอบเขต (ตั้งใจตัด):**
- **เกิน 3 พอร์ต** — เกินสามชุดกราฟอ่านไม่ออกและตารางล้นจอแคบ ซึ่งขัดหลัก P2 มากกว่าที่จะได้ประโยชน์
- **เงินเข้าออกแบบกำหนดเองรายเดือน** (ตารางที่ผู้ใช้กรอกทีละงวด) — ทำได้ด้วยการส่งออกไฟล์ไปคำนวณต่อ
  ส่วนในเครื่องมือรองรับเฉพาะแบบคงที่ตามรอบ ซึ่งครอบพฤติกรรมจริงเกือบทั้งหมด
- **ค่าธรรมเนียมและภาษีจากการปรับสมดุล** — ไม่มีในแผนทั้งโครงการ และการใส่ครึ่ง ๆ กลาง ๆ จะทำให้
  ตัวเลขดูแม่นกว่าความจริง
- **สินทรัพย์คนละชุดต่อพอร์ตพร้อมสกุลเงินคนละฐาน** — สกุลเงินฐานเป็นค่าร่วมของการเทียบ (ดู §9)
- **บันทึกพอร์ตไว้ใช้ครั้งหน้า** — ยังไม่มีระบบบัญชีผู้ใช้โดยตั้งใจ (R8) ลิงก์ทำหน้าที่นี้แทน

## §6 ลำดับการทำงาน (Flow)

1. ผู้ใช้ตั้งพอร์ตแรกเหมือนเดิม แล้วกด "เพิ่มพอร์ตเทียบ" ได้ถึงพอร์ตที่สาม
2. ค่าที่เป็นฐานการเทียบ (ช่วงเวลา · เงินตั้งต้น · สกุลเงิน · ตัวเทียบ · ปรับเงินเฟ้อ) กรอกครั้งเดียว
   ใช้ร่วมกันทุกพอร์ต · ค่าที่เป็นสิ่งที่กำลังทดลอง (สินทรัพย์ · การปรับสมดุล · เงินเข้าออก) ตั้งแยกรายพอร์ต
3. กดเริ่มทดสอบ → ชั้นข้อมูลดึงและแปลงสกุลเงินให้ทุกสัญลักษณ์ที่ใช้ในทุกพอร์ต **รอบเดียว**
   (สัญลักษณ์ที่ซ้ำกันข้ามพอร์ตไม่ดึงซ้ำ)
4. ชั้นคำนวณคิดผลตอบแทนรายเดือนของแต่ละพอร์ตตามวิธีปรับสมดุลของพอร์ตนั้น
5. พอร์ตที่มีเงินเข้าออก คิดเส้นมูลค่าจากตารางเงินเข้าออกด้วย และได้ค่าผลตอบแทนถ่วงน้ำหนักเงินเพิ่ม
6. ทุกส่วนของผลลัพธ์แสดงทุกพอร์ตซ้อนกัน โดยตัวเทียบยังเป็นเส้นอ้างอิงร่วมเส้นเดียว
7. ค่าที่ตั้งทั้งหมดถูกเขียนลงลิงก์ เปิดซ้ำได้ผลเดิม

## §9 กฎร่วมของ epic (Shared Rules)

### เจ้าของค่า — อะไรร่วมกัน อะไรแยกรายพอร์ต ([PD-014](../../decision-log.md))

การเทียบมีความหมายก็ต่อเมื่อ**เปลี่ยนทีละตัวแปร** ค่าที่เป็นฐานการเทียบจึงต้องร่วมกัน:

| ระดับ | ค่า |
| --- | --- |
| **ร่วมกันทั้งการเทียบ** | ช่วงเวลา · เงินตั้งต้น · สกุลเงินฐาน · ตัวเทียบ · ตัวเลือกปรับเงินเฟ้อ |
| **แยกรายพอร์ต** | ชื่อพอร์ต · สินทรัพย์และน้ำหนัก · วิธีปรับสมดุล · เงินเข้าออก |

| ID | กฎ |
| --- | --- |
| BR-CMP-01 | เทียบได้ตั้งแต่ 1 ถึง **3 พอร์ต** · พอร์ตเดียวคือการใช้งานปกติที่ต้องเหมือนเดิมทุกอย่าง |
| BR-CMP-02 | ค่าตามตารางข้างบน — ค่าร่วมมีที่กรอกที่เดียว ค่ารายพอร์ตมีที่กรอกในบล็อกของพอร์ตนั้น ห้ามมีสองที่กรอกสำหรับค่าเดียวกัน |
