# Epic: วัดผลการใช้งานจริง (usage-analytics)

**Status:** ✅ Done (S20b) · เส้นทาง: ⚪ → 🟡 → 🟢 Ready → 🔨 In Dev → **✅ Done**
**Roadmap:** งานข้ามเฟส เกิดหลัง S20 · **Session:** S20b author + implement

> **อ่านก่อน (TL;DR)**
> - วันนี้ไม่มีเครื่องมือวัดใด ๆ เลย จึงตอบไม่ได้แม้แต่คำถามง่ายที่สุดว่า **คนที่เข้ามาได้กดใช้ของจริงไหม**
> - จำนวนผู้เข้าชมของเว็บส่วนตัวแทบไม่มีน้ำหนัก · สิ่งที่มีน้ำหนักคือ **อัตราที่คนเข้ามาแล้วได้ใช้ของจริง**
>   ซึ่งไม่ได้มาฟรีจากการฝังสคริปต์ — ต้องนิยามเหตุการณ์ที่จะวัดเอง
> - epic นี้จึงเป็นงานออกแบบ **หกเหตุการณ์ที่ผูกกับคุณค่าของผลิตภัณฑ์** ส่วนการฝังตัวเก็บสถิติเป็นงานสิบบรรทัด
> - **ส่งรูปร่าง ไม่ส่งค่า** — จำนวนพอร์ตส่งได้ จำนวนเงินและชื่อหุ้นที่ผู้ใช้กรอกห้ามส่ง ([PD-027](../../decision-log.md))
> - ตัวเลขที่ได้เป็น**ค่าต่ำกว่าจริงเสมอ** เพราะตั้งความยินยอมเป็นปฏิเสธไว้ก่อน — ใช้เป็นอัตราส่วน ห้ามอ้างเป็นยอด

## §1 ปัญหา (Problem)

เครื่องมือถูกสร้างมาห้าเฟสโดยที่ไม่มีใครรู้ว่ามีคนใช้จริงหรือเปล่า และใช้ตรงไหน · ทุกการตัดสินใจ
เรื่องลำดับความสำคัญจนถึงตอนนี้มาจากการเดาว่าอะไรน่าจะมีค่า ไม่ใช่จากพฤติกรรมจริง

ปัญหาย่อยที่ตามมาคือ เมื่อจะเล่าผลงานนี้ให้คนนอกฟัง ก็พูดได้แค่ว่า "สร้างอะไรบ้าง"
พูดไม่ได้ว่า "แล้วมันได้ผลไหม" ซึ่งเป็นคำถามที่คนฟังสนใจกว่า

**สิ่งที่ทำให้ปัญหานี้ไม่ใช่แค่ติดตั้งสคริปต์:** ตัวเก็บสถิติแบบสำเร็จรูปบอกได้แค่ว่ามีคนเปิดหน้ากี่ครั้ง
ซึ่งไม่ตอบอะไรเลยสำหรับเว็บที่มีหน้าเดียว · คำถามจริงคือคนที่เปิดเข้ามา **ได้กดทดสอบพอร์ตไหม**
และนั่นต้องนิยามเอง

## §2 ผู้ใช้ (Persona)

- **เจ้าของ project ในบทบาทคนตัดสินใจว่าจะทำอะไรต่อ** — ต้องการรู้ว่าส่วนไหนมีคนใช้จริง
  เพื่อไม่ต้องเดาลำดับความสำคัญของเฟสถัดไป
- **นักลงทุนรายย่อยที่เข้ามาใช้เครื่องมือ** — ไม่ได้ร้องขอสิ่งนี้ และไม่ควรต้องแลกความเป็นส่วนตัว
  เพื่อให้เจ้าของเว็บได้ตัวเลข · เป็นเหตุผลที่ขอบเขตข้อมูลถูกจำกัดไว้แคบมาก

## §3 คุณค่า & ตัววัดความสำเร็จ (Value & Success Metric)

- **คุณค่า:** ตอบได้ด้วยข้อมูลว่าคนที่เข้ามาได้ใช้ของจริงแค่ไหน แทนที่จะเดา
- **ตัววัด (ต้องวัดได้):**
  - หกเหตุการณ์ปรากฏครบในบริการวัดผล เมื่อกดปุ่มจริงบนรุ่นที่ build แล้ว
  - คำขอที่ส่งออก **ไม่มีจำนวนเงินและไม่มีสัญลักษณ์ที่ผู้ใช้กรอก** แม้แต่ตัวเดียว
  - รันชุดทดสอบทั้งชุดแล้ว **ไม่มีคำขอออกไปหาบริการวัดผลเลยสักครั้ง**
- **หลักที่ยึด:** P5 ตัดสินด้วยข้อมูล ไม่ใช่ความรู้สึก · P3 ไม่ขอสิ่งที่ไม่จำเป็นจากผู้ใช้

## §10 ความเสี่ยง (Risks)

| ความเสี่ยง | ผลกระทบ | แผนรับมือ |
| --- | --- | --- |
| **ชุดทดสอบส่งข้อมูลปนเข้าไป** | ชุดรันสองร้อยกว่าข้อทุกครั้ง ตัวเลขที่จะเอาไปใช้กลายเป็นของเครื่องตัวเอง | สองด่านอิสระ (BR-USE-03, BR-USE-04) + เทสต์ที่ยืนยันว่าไม่มีคำขอออกไปเลย |
| **นับหน้าใหม่พองเพราะที่อยู่เปลี่ยน** | หน้าผลลัพธ์เปลี่ยนที่อยู่ทุกครั้งที่กดทดสอบ จำนวนผู้เข้าชมจะพองตามจำนวนครั้งที่กดปุ่ม | ปิดการนับหน้าใหม่จากการเปลี่ยนที่อยู่ ที่ฝั่งตั้งค่าของบริการวัดผล — **โค้ดสั่งไม่ได้ เป็นงานฝั่ง PO** |
| ข้อมูลผู้ใช้หลุดไปกับเหตุการณ์ | เก็บสิ่งที่ไม่ได้ขอและไม่ได้ใช้ | ตรวจ**เนื้อคำขอจริง**ตอนเดินหน้า ไม่ใช่เชื่อว่าเขียนถูก |
| ฝังแล้วหน้าช้าลง | ขัดกับคุณค่าหลักของเว็บ | โหลดแบบไม่ขวางการแสดงผล + งบเวลาเดิมยังต้องผ่าน |
| ตัวเลขต่ำกว่าจริงจนตีความผิด | สรุปผิดว่าไม่มีคนใช้ | เขียนกำกับไว้ใน §9 และในการ์ด · ใช้เป็นอัตราส่วนเท่านั้น |
