## หมายเหตุ UX

**หน้าจอ/ส่วน:** แถวปุ่มท้ายฟอร์ม

**ก่อน / หลัง:**
```
ก่อน:  [ เริ่มทดสอบ ]

หลัง:  [ คืนค่าเริ่มต้น ]                      [ เริ่มทดสอบ ]
       └ ซ้ายสุด                                 ชิดขวา ┘

ระหว่างตรวจสัญลักษณ์:
       [ คืนค่าเริ่มต้น ] กำลังตรวจสัญลักษณ์…    [ เริ่มทดสอบ ]
```

ปุ่มคืนค่าเริ่มต้นใช้แบบมีเส้นขอบ ปุ่มเริ่มทดสอบใช้แบบทึบ — น้ำหนักสายตาบอกว่าอันไหนคืองานหลัก
โดยไม่ต้องอ่านคำ

**5 สถานะ UI:**

| สถานะ | เกิดเมื่อ | ผู้ใช้เห็นอะไร |
| --- | --- | --- |
| ว่าง (Empty) | เพิ่งเปิดหน้า | ปุ่มอยู่ครบทั้งสอง กดได้ทั้งคู่ |
| กำลังโหลด (Loading) | กำลังคำนวณ | ทั้งสองปุ่มกดไม่ได้ (BR-LOOP-22) |
| ผิดพลาด (Error) | รันไม่สำเร็จ | ปุ่มกลับมากดได้ · กดคืนค่าเริ่มต้นแล้วข้อความผิดพลาดหายไปด้วย (EC-LOOP-08) |
| สำเร็จ (Success) | มีผลแล้ว | กดคืนค่าเริ่มต้นแล้วทั้งฟอร์มและผลกลับไปเป็นหน้าเปล่า |
| สำเร็จบางส่วน (Partial) | ไม่มีกรณีของการ์ดนี้ | — |

**การโต้ตอบสำคัญ:** กดครั้งเดียวจบ ไม่ถาม ไม่มีขั้นตอนยืนยัน (BR-LOOP-19) ·
**ทางเลิกทำคือปุ่มย้อนกลับของเบราว์เซอร์** ซึ่งพากลับไปที่ผลเดิมครบทุกค่า

**การเข้าถึง (WCAG AA):** ปุ่มเป็น `<button>` จริงที่โฟกัสได้ · ลำดับการกด Tab เรียงซ้ายไปขวา
ตรงกับที่ตาเห็น · ปุ่มคืนค่าเริ่มต้นเป็นชนิด "ปุ่มธรรมดา" ไม่ใช่ปุ่มส่งฟอร์ม เพื่อไม่แย่งพฤติกรรม
การกด Enter (BR-LOOP-21)

**Responsive:** สองปุ่มอยู่บรรทัดเดียวกันบนจอ 375 จุด (ยืนยันแล้ว) โดยคืนค่าเริ่มต้นชิดซ้าย
และเริ่มทดสอบชิดขวา

**ข้อจำกัดข้อมูลจำลอง (stub limitation):** ไม่มี

**คำเตือนการลงทุน:** ข้อความเดิมตาม BR-MVP-02 ไม่เปลี่ยน

- **Guards:** lint · tsc · vitest · build · e2e ทั้ง repo
